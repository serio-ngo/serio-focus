---
name: plugin-lifecycle
description: Use when editing plugins/serio-focus/scripts/lifecycle/ (publish.mjs, push.mjs, route.mjs, acceptance.mjs, lock.mjs), the scripts the lifecycle workflows run. Covers the spec-review result, its criteria table, the acceptance report, the test lock and the run archive.
---

## Exports

| Script | Export | Contract |
|---|---|---|
| publish.mjs | `comment(out, sha, extra?, spec?)` | spec-review result to the review comment body; `null` for an invalid result; `spec` is the issue body: when the review has fewer `e2e` criteria than the numbered criteria in the spec's `### Acceptance criteria` section labelled e2e (opening bold label or `Level: e2e`, case-insensitive), the body holds `Levels: the spec names <N> e2e criteria; this review has <M>.` |
| publish.mjs | `logText(rows, isPrivate)`, `transcriptFile(rows)`, `evalOf(file)` | redacted trace lines, and in a private repository every transcript row; one redacted JSON row per line; the eval file parsed, every string redacted |
| publish.mjs | `archive({ repo, run, attempt, stage, at, transcript?, evaluation, gate?, artifact?, isPrivate, to }, io)` | `io` is `{ one, all, send, drop, scan, sleep }`; one `PUT` to `repos/<to>/contents/runs/<repo>/<YYYY-MM-DD of at, UTC>/<run>-<attempt>-<stage>.json` holds the record `{ trace, eval, result, gate, revision, plugin, model, effort, dropped }`; `trace` is `trace.mjs` of the transcript with `errors`, `denied` and `repeats` as per-tool counts of their entries; no release is created and no asset uploaded; assets of `raw-*` releases created more than 90 days before `at` are deleted; `outcome(rows)` adds `revision`, the `git rev-parse HEAD` of the checkout it runs from, to the eval, and `archive` records the eval's `revision` when it has one, else the checkout's; `scan(dir)` of `lib/gitleaks.mjs` returns the flagged `<field>.json` names, `verified(name, buffer)` there checks a release archive against the pinned sha256; returns `{ ok, note }`, never throws |
| publish.mjs | `--gate <file>`, `--archive`, first argument | `--gate` and `--archive` print `::error::<note>` and exit 1 (`--archive` also puts the note into the eval file); `--gate` archives the gate record as `gate` of stage `gate`, with run, attempt, repository and `at` from the record, no transcript; a first argument that is not `--archive`, `--gate`, `--outcome`, `--log` or an issue number prints `not an issue number: <argument>` and exits 1 before any `gh` call |
| publish.mjs | `pushed({ repo, number, stage, before, spec, note, reason }, io?)` | `io` is `{ one, all, send, raw }`, real `gh` by default, shared by `status` and `park`; a head differing from `before` removes `needs-human` and, for `write-tests`, posts `<!-- write-tests v1 spec=<spec, else specSha of the issue> -->` on the issue; the pull request is the open one whose `taskOf` is `number`; equal parks with `the run ended without a new push: <run link> (<stage>).`, unless `stage` is `deliver` and the pull request is ready; `pr-loop` parks the pull request, its reason ending with `pr-loop does not start again on head <head>.`, a status log line `status` never trims; `main()` passes environment and argv, `SPEC_SHA` as `spec` |
| push.mjs | `publishCard({ repo, out, issue, ref, stage }, io?)` | the run without a commit bundle; same `io`; for `stage` `deliver` with `pr.md` in `out`, sets the open pull request of `ref` to the issue title and the card and marks it ready; otherwise sends nothing; reads no environment |
| route.mjs | `route(name, event, state)` | `{ stage, issue, … }` starts a run, `{ stop, tell }` does not; a code owner's `spec-ok` that accepts reviewed criteria adds `accept`, the ready review to post; `write-tests` from `spec-ok` stops when the newest `github-actions[bot]` marker `<!-- write-tests v1 spec=… -->` on the issue names the current spec and no trusted status comment of the issue or of the task draft holds a park of a `write-tests` run later than that marker, and any `write-tests` start after two such markers returns `{ park: <issue>, stop }`; a started `write-tests` carries `spec`, the spec hash at the start, and without a pull request `sha`, the head of the open draft whose `taskOf` is the task; `pr-loop` from a red CI stops when a trusted status comment of the pull request holds `pr-loop does not start again on head <head>.`; `state.branch(name)` tells whether a branch exists in serio-ngo/serio-focus; a started stage carries `focus`, the branch named by the newest code-owner comment on the task issue holding `<!-- improve v1 focus=<branch> -->`, when it matches `improve/[a-z0-9-]+` and exists, else empty; `main()` writes it as the output `focus` (the agent job loads skills, agents and hooks from it; every job holding a write token runs scripts from `main`) |
| acceptance.mjs | `cases(xml)`, `report({ issue, review, tests, sha, lock?, link?, files?, size?, free?, skipped?, fails?, without?, repeats? })` | JUnit XML to `[{ name, result }]` (`passed`, `skipped`, `failed`, `load error`: a failure matching `Failed to load url`, `Cannot find module`, `ERR_MODULE_NOT_FOUND` or `does not provide an export named`; `load error` fails the report); `review` is the trusted spec-review body, `tests` the `cases` output; each line of `fails` fails the report; `without` is the `cases` of the run with every production file reverted: a criterion whose test passed there adds `Passes without the change: AC<n>, …` and fails; `repeats`, `[string, files]` pairs, add the line ``Routes in two or more files: `<string>` in `<file>`, `<file>` `` and fail; `report` returns `{ ok, body }` |
| acceptance.mjs | `accept({ repo, number, dir, tested, lock, link, post, revert }, io?)` | `io` is `{ one, all, send, raw }`, the real `gh` calls by default; builds the report for `tested`, or for the current head when `tested` is empty, and with `post` writes or edits the one report comment; when `tested` is not the current head it sends nothing and returns `ok: true` with a one-line body; reads no environment; in the pull request's files a test case is an added patch line of a test path (a locked path that is no `.claude/` or `.agents/` skill and no gate config) starting with `it(` or `test(` and a quoted name, or with `def test_<name>` (also `async def`); its fail lines are `Tests only: the pull request adds test cases and changes no production file`, ``Test cases no criterion names: `<name>`, `<name>` `` (a name equal to no criterion's test nor to its last ` › ` segment), `More test cases than criteria: <cases> for <criteria>` and `More than 40 added test lines per criterion: <additions of test paths> for <criteria>`; a pull request without a lifecycle task has 0 criteria, posts nothing and returns `acceptance: not a lifecycle pull request` plus its fail lines and the routes line, `ok` false when there is one; `revert` is the folder `--revert` writes: `without` comes from `all/`, or from the head's results when no production file changed; ``Changes no test needs: `<path>`, `<path>` `` lists each file whose `<i>/` run passes every criterion test and `Not reverted in time` the paths in `skipped`, both report-only; `routes.json` gives `repeats`; no such line when the folder is missing; `main()` passes `REVERT`, `TESTED_SHA`, `LOCK_NOTE` and the run link, prints `body` and exits 1 when `ok` is false |
| acceptance.mjs | `record({ repo, number, dir, tested, lock, note, verifier, run, attempt, jobs }, io)` | `io` is `{ one, all, raw }`; `lock` is the lock step outcome; returns `{ repository, pr, run, attempt, at, head_sha, tested_sha, reported_sha, verifier, lock, acceptance, cases, jobs }`: `lock` is `test lock: <pass\|fail> - <note>`, `acceptance` the body `accept` builds without posting and without the run link (`null` unless the outcome is `success`), `reported_sha` the sha its marker names or `null`, `cases` the JUnit cases; `acceptance.mjs <PR> <dir> --record <file>` writes it from the gate job's environment |
| acceptance.mjs | `--revert` | run from the repository root; env `BASE`, `UNIT`, `E2E` (may be empty); production files are those added or changed between merge-base(HEAD, BASE) and HEAD that are not a locked path (lock.mjs), not gate config (`CONFIG`) and not Markdown; app source is a production file under a `src/` or `app/` folder, not `.mdx` and not under a `content/` folder below it; first, when the pull request adds to app source a string that two or more app source files at HEAD hold, writes each such string with those files to `revert/routes.json` as `[[string, [files]], …]`: a string is a quote, backtick or `}` then `/` and a word character up to a quote, backtick, `$`, `?`, `#` or `)`, cut to its first two non-empty path segments (`/en/` is `/en`), or `http://` or `https://` and a host; a path whose last segment has an extension and hosts ending in `w3.org`, `schema.org`, `sitemaps.org` or `schemas.android.com` are skipped; then, when a production file changed, one run with all of them reverted into `revert/all/` (`file` lists the paths, one per line), then for each in order i: restore from the merge base (remove when new), run `UNIT` then `E2E` with `bash -c`, move `junit/*.xml` into `revert/<i>/`, write the path to `revert/<i>/file`, restore from HEAD; the paths of a run the 12-minute budget (`REVERT_BUDGET_MS`) cuts are listed once each in `revert/skipped` |
| lock.mjs | `check({ pr, issue, comments, reviews, own, changed })`, `load(repo, number, io?)` | `check` returns `{ ok, locked, note }`; `changed(lock)` returns paths changed after the lock, or `null` when the lock is not in the branch history; `load` takes `io` `{ one, all, raw }` and returns the input of `check` |

## Data

| Data | Lives in |
|---|---|
| Spec-review result shape | `scripts/lib/spec-review.schema.json`; each criterion has `id`, `text`, `level` and `test`; the test is in the Test column of the criteria table in the spec-review comment |
| Run hand-off | `eval.json` in the `eval-*` artifact, written by `publish.mjs --outcome`, holds `structured`, `note` and `reason`, read by the publish job, never from job outputs; the transcript is artifact `transcript` |
| Archive | `to` of `archive`; record `runs/<repo>/<date>/<run>-<attempt>-<stage>.json`, gate record `…-gate.json` written by the control job of `lifecycle-gate.yml`; gitleaks version and checksums `scripts/lib/gitleaks.mjs` |
| Trusted spec review | the comment `specComment` in `scripts/lib/lifecycle.mjs` returns |
